# HashLine 变长动态锚点规格（v2.0 定案）

**Status**：定案（2026-08-31）。来源：wayfinder map 讨论定案（#57 哈希与分配算法实测、#58 变长锚点分配机制定案、#59 锚点格式与契约定案）与 spec issue（#63）。
**Supersedes**：[`docs/dynamic-hashline.md`](./dynamic-hashline.md)（v1.0 设计稿）。v1.0 保留为历史稿，其中与本文冲突之处以本文为准。
**适用场景**：AI Agent 文件行级读写/编辑工具（HashLine）。

---

## 1. 目标与背景

为 Agent 编辑工具中的每一行分配**内容可寻址、最短优先、会话内永不失效**的短锚点，并保证「agent 持旧锚编辑绝不静默改错行」。

相比 v1.0 稿的三处根本修正（实测驱动）：

1. **步长函数缺陷**：`step = (hash % (total - 1)) + 1` 与 `total = 62^d` 共享因子时，探测环只覆盖部分槽位（「真随机」哈希下 2 位层仅能填 53.4%）；cyrb53 的步长偏向奇/大值恰好掩盖了它。必须显式修正。
2. **复制行坍缩**：v1.0 的 content_map 让相同内容共享锚点，空行等重复行将无法独立寻址。改为**每行唯一锚**。
3. **范围错误防线**：v1.0 的槽位复用会在「旧锚 → 新行」时静默打错行。业界纯哈希方案的「命中 ⇔ 内容相等」防线必须移植为目标机的 served 内容校验。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 锚点（anchor） | 分配给某文件行的变长 Base62 标识（深度 2–4 起步），会话内唯一。Agent 视为不透明标识符。 |
| natural 槽 | 行内容哈希对某层槽位总数取模得到的首选槽位。 |
| 探测（probing） | natural 槽被占用时按步长序列寻找的下一个空闲槽。 |
| spill | 探测超过上限后放弃当前层，向下一层（更长）分配。 |
| 命中规则 | 编辑请求被接受的条件：槽被占用 ∧ 当前行内容 == 服务时行内容。 |
| served | 工具输出（read/grep/edit diff）服务过的行及其「锚 → 服务时行内容」记录。 |

## 3. 锚点格式契约

- **形态**：变长 Base62（字符集 `0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`），`[A-Za-z0-9]{1..4}`（实施上限 4 位，超限自动上浮）。
- **无前缀**：不使用 `@`（实测使 2 位锚的 token 收益抹平至 0%）。锚是**不透明标识符**，禁止解读其长度或内容。
- **行号退出锚点**：行号不参与锚点身份。可选**输出**参数（per-call boolean，默认 false）渲染为 `<line>:<anchor>`（`:` 分隔，与旧 `line#hash` 的 `#` 形态区分）；仅作「当前行在哪」的提示。
- **输入解析**：接受裸锚 `[A-Za-z0-9]{1..4}`，或对称接受 `<line>:<anchor>`（行号作**弱提示**：不符仅附 warning，不拒绝；内容校验为权威）。
- **旧格式**：`line#hash` 不兼容解析、不附提示，直接判 `E_BAD_REF`；3 位裸 hash 与新锚同字符集，天然兼容（无特判）。
- **渲染位置**：read / grep / edit diff / undo 输出行左列统一为 `<anchor>`（或开启行号时 `<line>:<anchor>`），右列保持 verbatim 文件内容；响应仍以 `ANCHOR:FILELINE` 头开始。

## 4. 分配机制

### 4.1 哈希

沿用现有内容哈希（cyrb53）：实测与 BLAKE2b-64 均匀性持平（χ² 3,850 vs 3,827），吞吐快 12.9×（15.79 vs 1.22 Mops/s），零新依赖。不引入 BLAKE2b-64 / XXH3。

### 4.2 分层与探测

- 每行**独立最短优先**：分配永远从深度 2 开始检索（v1.0「分层水位线」措辞为误导，实为逐行贪心最短）。
- **双哈希探测**：`start = hash % total`、`step = (hash % (total - 1)) + 1`，序列 `idx = (start + offset·step) % total`。
- **步长修正**：拒绝与 `total = 62^d = 2²·31²` 共享因子的步长；非互素时回退 `step = 1` 线性探测。
- **探测上限 64**：超过立即 spill 到下一层（分配成本有界；2 位层满填 ~98%，对压缩比影响可忽略）。
- **深度上限 4**（`62^4 ≈ 14,776,336`）；超过自动上浮 5 位层（`62^10` 理论上限不可达，「哈希空间耗尽」不会发生）。
- 容量参考：2 位层 3,844 / 3 位层 238,328 / 4 位层 14,776,336。2 位层定位为**压缩比**而非容量。

### 4.3 复制行（每行唯一锚）

内容相同的行与内容不同但哈希重复的行处理**一致**：统一视为冲突，走探测获取新空闲锚。content_map 仅作「内容 → 上次锚」提示，无复用路径。「同内容同锚」仅在单次出现且 natural 槽空闲时成立。

### 4.4 分配状态载体

- **会话态 per-path 快照**，沿用现有「快照 + 内容校验和失效」缓存模式，**不落盘**。
- 工具自持编辑按已知 delta 增量更新（删行释放、插行分配）；首读或外部变更（校验和不匹配）时从当前内容**全量确定性重算**——确定性保证未变更文件跨会话（重启）锚一致。
- 承诺边界：会话内 + 存活期内绝对不变；跨会话对未变更文件一致，churn 过的文件按新状态重算（已知权衡，接受）。
- **跨文件不共享**：锚 per-path 独立；跨文件引用必然 E_STALE（行为变化，无害）。

### 4.5 回收与 update

- **回收**：释放的槽位会话内**立即复用**（保留 v1.0 需求 #4 意图）；安全性由命中规则（§5）保障。
- **update**：行内容变化 = 释放旧锚 + 为新内容分配新锚（与其他行相同则按 §4.3 独立分配）；noop 不触发。

## 5. stale 防护与错误码

### 5.1 命中规则（served 内容校验）

服务行时记录「锚 → 服务时行内容」（served 记录扩展，可存 64bit 内容摘要）。编辑解析流程：解析锚 → 定位当前占用该锚的行 → **比对当前行内容与服务时内容**：

- 不同 → `E_STALE` 硬错误，回显 = `ANCHOR:FILELINE` 头 + 锚定行 ±3 行（行号开关跟随调用参数）+ 一行「该内容当前位于行 N, M, …」提示；回显行入 served 供直接重试。
- 相同 → 放行。

该规则是业界纯哈希方案「命中 ⇔ 内容相等」防线的移植（决策依据：kebbbnnn/hashline、quangdang46/hashline、can1357/oh-my-pi——三者均以内容相等为命中条件，结构性免疫「旧引用 → 新行」范围错误；「每行最短 + 无冲突」必须有分配状态，业界无此先例，故须自建此防线）。

### 5.2 错误码映射（枚举不变，语义重映射）

| 错误码 | 触发 |
| --- | --- |
| `E_BAD_REF` | 非 `[A-Za-z0-9]{1..4}` 形态（含旧 `line#hash`、含 `@`、超长） |
| `E_STALE` | 锚不存在（槽空未分配）或 served 内容校验失败（内容已变） |
| `E_RANGE_UNSERVED` / `E_RANGE_UNVERIFIED` | 沿用既有定义（服务区校验） |

复制行无需新错误码（每行唯一锚已消歧）。

## 6. 工具契约面

- **输出**：read / grep / edit diff / undo 的行前缀为裸锚（或开启行号参数的 `<line>:<anchor>`）；diff 块、Warnings / Drift / Snapshot id 保留。
- **Shift 块删除**：0.4 的 `Shift:` 位移链与 `newLine#oldHash` 指引移除——行号已退出寻址，agent 后续操作直接重新 read 取锚。
- **prompts / guidance**：更新 READ / EDIT / GREP / UNDO 描述与 guidance（锚为不透明标识符、复制不猜、命中规则、可选行号参数说明）；具体措辞随实施落地。

## 7. 配置

`hash_length` 配置**删除**（变长为机制承诺，配置与最短优先冲突）。存量配置标注 deprecated 并忽略；README / CHANGELOG 记录迁移。

## 8. 性能与内存预算

- 分配：探测上限 64，单行成本有界；全量重算（1M 行）实测推演 ~数十 ms（探测总量级数 M）。
- 内存：会话态地图 1M 行估算 100–200 MB（锚点字符串 + 映射开销）。
- 删除重插锚变化率（跨会话 churn 后重算）：实测 0.4–0.6%（500 轮 churn）。
- Token 收益：变长 2-first 对比固定 3 位，103 行样本实测省 3.0%（−103 字节）；无 `@` 前缀时该项收益不被抹平。

## 9. 测试缝（已确认）

- **S1 — 工具契约测试（主缝）**：以 read/edit/grep 公开行为为缝，复用现有 serve/verify 测试模式：变长锚输出形状、可选行号参数、served 内容校验的 E_STALE 路径、复制行每行唯一锚、删除回收后旧锚失效、确定性重算跨调用稳定。
- **S2 — 分配器纯函数单测**：探测（互素回退 + 上限 64 + spill）、释放回收、update；纯函数无 IO，与现有哈希纯函数测试同款。
- 好测试标准：只测外部行为（锚形状、E_STALE 触发、复制行独立性、回收复用结果、性能上界），不测实现细节。
- 基准复测与真机冒烟为独立门禁（不属本规格测试缝）。
