# ADR-0039: 自动诊断是回归信号——诊断身份与抑制账本

## 背景与问题

自动诊断（写后推送）把服务器对**整个文件**的意见全量投递：编辑一个本就带着几十条既有类型告警的文件时，模型每次写入都收到同一批诊断。噪声淹没了唯一的信号——「这次改动有没有引入新问题」——模型要么无视该渠道，要么浪费 token 逐条确认（#429 问题陈述）。

同时，投影层丢弃了协议里的 `source`（哪个服务器说的）与 `code`（规则句柄），「类型错误 / 语法错误 / lint 建议」的区别在界面上不存在。

## 决定

### D1 — 自动诊断是回归信号，不是状态快照

一次写入的报告只谈**本次新增**；已见诊断用一行汇总收口（「另有 N 条与上次相同」）。全量状态由 `lsp diagnostics` 主动查询承担——两个面语义分明、互不污染，主动查询不去重、不写账本。

### D2 — 诊断身份 = `severity + source + code + 规范化 message`

空白折叠、保留大小写、**不含行号**（上下行插入导致的行号漂移不重报）；缺 `source` / `code` 以空串参与比较；同一身份重复出现按多重集计数（重复本身是事实）。身份以纯函数暴露（`diagnostics/identity.ts`），账本与投影共用一套规则。

### D3 — 抑制账本：进程内、有界、投递时记账

- 作用域 `(会话键, 文件绝对路径)`，进程内 Map，不持久化——重启后首报全量（状态重新可信）。
- **投递成功时**记账（内联拼进工具结果、或异步注入被接受）；投递失败不记账，诊断不静默丢失。
- **遗忘**：账本只保存「上次投递的全集」；本次推送不再出现的身份即遗忘，重现即新增。
- 有界：≤200 文件 × 每文件 ≤200 身份，LRU 淘汰；被淘汰的文件下次写入重新基线（全量报一次，诚实的代价）。

### D4 — `source` / `code` 原样透传，不判型

四面（模型文本、JSON 信封、卡片、主动查询）共用同一行格式：`error(pyright/2322): <message>`；缺一退化为 `error(2322)` / `error(pyright)` / `error: <message>`。JSON 信封在 `messages` / `severities` 旁给出**等长对齐**的 `sources` / `codes`。**不做任何判型**——协议没有「类型 vs 语法 vs lint」的维度，判型只能按服务器写死规则且随版本漂移；透传句柄是不撒谎的替代。

### D5 — 投影顺序与两个独立事实

身份过滤在前、50 条上限截断在后；「被上限砍掉」与「被抑制」是不同事实，各自成行。纯抑制（新增为零）不输出 head 与行块，只输出一行汇总；胶囊仍渲染（该文件诊断状态的常驻指示），文案追加「N 未变」。

## 后果

- 动态语言文件的长编辑会话不再被旧告警淹没；回归信号可读。
- `lsp diagnostics` 成为唯一的全量面（规格明确，行为不变）。
- 旧会话持久化 meta 缺 `sources` / `codes` / `suppressedCount` 时客户端按缺省容错，不报错。
- 不新增设置项；既有「延迟报告只谈最新写入」契约不变，本机制叠加其上。
